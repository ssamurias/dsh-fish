# DSH Fish：Session 综合负担评分设计文档

> 第一阶段只读分析方案 | 版本 1.0 | 2026 年 11 月 15 日

目标项目：ssamurias/dsh-fish（大肥鱼） \| 目标使用场景：长期人格 Agent 的日常聊天与多工具调用

# 执行摘要

本方案不是一套新的记忆系统，也不是对 DSH 自动压缩或大肥鱼人格成长机制的改造。其唯一目标是：从当前及历史 Session（包括归档会话）中获取本地可用的数据，计算综合累计使用负担，解释不同聊天轮次和工具行为造成的负担，帮助使用者评估目前“约 40 轮换房”是否符合个人使用习惯。

第一阶段只实现评分、只读采集、历史回填、可配置指标和同级设置页面。不自动换房、不拦截压缩、不调整 40 轮设置、不调用 LLM、不联网。所有公式参数是可验证的初始方案，不能当成已经验证的最优参数。

# 一 已确定的产品边界

| **事项**   | **第一阶段明确规则**                                                                |
|------------|-------------------------------------------------------------------------------------|
| 现有换房   | 默认 40 轮；保留原有上下调整和既有交接机制，不改动。                                |
| 主动压缩   | 不监控触发控制，不拦截，不覆盖或关闭 DSH 自动压缩。可只读记录已发生的压缩事件。     |

| 资源消耗   | 零新增 LLM 请求、零新增模型 Token、零外部 API；本地统计仍占用少量 CPU、内存和磁盘。 |
| 数据采集   | 尽可能收集宿主已有的有效数据；默认七个维度全部纳入评分，每项可独立关闭。            |

| 历史范围   | 优先大肥鱼主会话及其历史换房链，包括归档；其他 DSH 会话默认不混合为人格基线。       |

# 二 评分究竟代表什么

压力分不是健康值、浪费值，也不是“模型快爆炸的概率”。它度量当前 Session 到目前为止的综合使用负担，相对于该用户在相同指标口径、相近模型配置与指定参考轮数下的典型历史结束负担。

基准约定：100 分 = 当前参考轮数 N（默认 40 轮）时，历史可比较 Session 的典型结束负担。50 分表示综合指标约为该参照的一半；120 分表示约高 20%。它不等价于 Token 数量高 20%。分数允许超过 100，不强制封顶。

必须同时显示客观安全数据：当前 Context、模型窗口、有效压缩阈值和剩余空间。即使用户关闭容量维度，这些客观安全数据显示也不应消失。

# 三 数据来源和统一口径

| **数据**               | **预期获取方式**               | **原则**                                                  |
|------------------------|--------------------------------|-----------------------------------------------------------|
| Turn / Step / 请求     | DSH Session 事件               | 按事件序号与轮次关联，避免重复汇总。                      |
| 输入 / 输出 / 总 Token | 已存的模型 Usage               | 总量优先用宿主实报，缓存/推理细项不再加到已包含的总量。   |
| Context / 模型窗口     | Token Meter + request/context  | 区分估算压力、实报 Token、Context Window 和有效压缩阈值。 |
| 工具结果               | tool/call、tool/result 与投影  | 只保存估算大小、来源及可见性统计，不复制正文。            |
| 缓存读写               | 供应商适配器的 Usage           | 有字段才分析，不把缺失视为 0。                            |
| 压缩与替换             | compaction 事件 / Surface 替换 | 分段计算；压缩后的负增长不当成普通轮次净增长。            |
| 历史归档               | Session Persistence 的只读访问 | 无须恢复、解档、唤醒 Agent 或取得写锁。                   |

同模型可比较的定义：provider、model、Context Window、计量估算版本、有效压缩策略一致或明确完成口径转换。变更路由的会话按段统计，不盲目拼接。模型实际实报 Token 与本地消息估算 Token 不应混作同一字段。

# 四 七个累计负担维度与具体公式

定义当前 Session 第 n 轮的七维累计原始量 L(j,n)，历史基准 B(j,N)，启用集合 J，初始权重 w = (0.15,0.15,0.15,0.15,0.15,0.10,0.15)。

核心公式：S(n) = 100 × \[Σ(j∈J) w(j) × L(j,n)/B(j,N)\] / \[Σ(j∈J) w(j)\]。

B(j,N) 推荐采用固定版本参考样本中，正常到达第 N 轮的对应维度中位数；如果基准为 0、缺失或不可比较，此维度在当前完整评分中标记不可用，不能硬除以 0。指标开关改变后使用相同历史样本集与同一口径重新计算。

## 4.1 上下文容量 C 权重 15%

C(n) = max(i≤n) \[c(i)/t(i)\]²。c(i) 为有效上下文估算；t(i) 为当时有效压缩阈值。

选择峰值而非最终值，是为了避免 Session 压缩后压力回落使累计负担突然消失；平方仅表达高占用更重要的初始偏好。模型切换与压缩事件需要额外标注。

## 4.2 增长负担 G 权重 15%

g(i) = max(0, c(i)−c(i−1))，且只在连续同口径样本内计算。G(n) = \[Σg(i) + λΣmax(0,g(i)−q75)\] / t(ref)。初始 λ=0.5。

q75 为可比较历史轮次正增长的 75% 分位；第二项提高突发增长的贡献，同时保留累计增长。样本不足时可暂不加突发修正，而非凭空制造 q75。

## 4.3 Token 总消耗 U 权重 15%

U(n) = Σ(i=1…n)Σ(r=1…m(i)) usageTotal(i,r)。这里使用每次请求实报总 Token，不重复叠加输入、输出或已包含的缓存/推理字段。

缺失的 Usage 记为 unknown；完整和不完整轮次须分开展示。不能把缺项当零后再给出精确累计总数。

## 4.4 请求放大 A 权重 15%

A(n) = Σ(i=1…n)Σ(r=2…m(i)) inputTokens(i,r)。它衡量同一用户聊天轮次内，第二次及之后模型请求的累计输入负担。

这并非独立计费量，已经部分包含于 U；保留它是为了识别工具链带来的调用模式，而不是多算一次真实成本。UI 必须明确“结构性负担”标签。

## 4.5 工具结果残留 T 权重 15%

T(n) = Σ(j) s(j) × Σ(r≤n) v(j,r)，其中 s(j) 是工具结果估算 Token，v(j,r)=1 表示该结果在第 r 次后续请求的模型可见 Surface 中仍存在，否则为 0。

单位为 Token·请求次数。它能够区分“一次输出很大但快速被裁剪”和“中等输出长期留在 Context”。若事件重放不足以可靠判断可见性，标记为估算，不应虚构精确占用。

## 4.6 缓存复用 K 权重 10%

K(n) = Σ(r=1…M(n)) max(0, inputTotal(r)−cacheRead(r))；仅在供应商提供兼容缓存读取字段时计算，并先统一输入口径。

这个指标是未通过缓存读取复用的输入负担，不是货币成本修正；用户已明确不需要查价格。若供应商不报缓存，则维度不可用，不能把缓存读视为 0。

## 4.7 失败与恢复 E 权重 15%

E(n) = Σ(r∈F(n)) usageTotal(r)，F(n) 仅包含可从宿主事件明确判别的失败、重试或重复执行请求。

不应笼统把工具报错之后整轮消耗计为无效，也不对模型工作质量做额外 LLM 判断。这是失败与恢复负担，不叫“浪费成本”。

# 五 数据重叠和可解释性

七维不是七种互相独立的实际 Token 账单。U 与 A、T 和 K 存在有意重叠，用来表达总量、调用模式、工具长期占用及缓存复用四种使用负担。因此 S 是用户定义的综合分析指数，不是总 Token 的物理换算。

第一版保留初始权重，并在详情页显示每项归一化贡献 w(j)×L/B。不要在缺少足够历史样本时自动做 Spearman 相关性“智能降权”，防止同一 Session 的分数因少量新样本频繁跳动。后续可通过历史数据评估冗余性。

# 六 指标开关与配置版本

- 七项默认全开，可分别启停；关闭只影响评分，仍持续采集该指标。

- 剩余权重重新归一化；只要一项被关闭，当前分数、历史曲线和参考阈值必须在相同启用集合下重算。

- 页面同时保留“当前自定义评分”和“默认全指标参考评分”，允许比较，但须解释口径不同。

- 每个配置保存 enabled 维度、权重、基准版本、评分算法版本和创建时间；历史记录不因重新计算被覆盖。

- 全部关闭时显示“无可计算分数”，而非 0。

# 七 历史样本和合理换房压力的判断

历史典型值不是最佳值。过去 40 轮常见 100 分只能说明该设置的使用习惯，不证明它安全、省 Token 或最佳。合理换房参考需要同时显示正常结束分布、实际压缩记录、边际负担与样本可信度。

对于参考轮数 N：Ŝ(N)=median{S_i(N)}，只用确实达到 N 轮且可比较的 Session 估计典型负担；同时列出 P25、P75、P90 与样本数。提前压缩或在 N 轮之前停止的 Session 不能简单删除，应作为截尾/风险样本单独统计，避免幸存者偏差。

边际负担：M(n,k)=\[S(n)−S(n−k)\]/k，默认 k=5。用历史同类工具强度下的轮次作为对照，以免把“后期任务更复杂”错误归因于“Session 太长”。

参考值分三类：典型水平（历史中位数）；稳妥参考（结合未压缩样本与风险事件）；充分利用参考（安全样本中的较高分位）。只有足够压缩事件和同口径样本时才标注稳妥/充分利用，否则明确写“证据不足”。

不对超出可观察历史长度的轮数做伪精确外推；例如仅有 40 轮历史时，50、60 轮显示样本不足。历史参考应按具体算法/配置版本固定，不因新样本默默变化。

# 八 历史 Session 回填与归档处理

| **操作** | **行为与约束**                                                                          |
|----------|-----------------------------------------------------------------------------------------|
| 发现     | 从 DSH 的可用 Session 列表、工作区和归档索引发现旧 Session，结合大肥鱼会话链身份识别。  |
| 读取     | 通过 Session Query / Persistence 的只读能力读取历史事件；不解档、不唤醒、不创建新会话。 |
| 重建     | 按事件顺序还原轮次、请求、工具、Surface 替换与压缩；逐项记录实报/估算/未知。            |
| 保存     | 独立保存统计缓存、算法版本、事件游标与会话 ID，不复制原始聊天和工具正文。               |
| 故障     | 单条损坏 Session 记录原因并跳过；不影响其他 Session、宿主聊天或插件启停。               |
| 性能     | 首次分批回填，后续增量处理；页面访问只读缓存，避免每次重扫。                            |

# 九 UI 详细规格

入口：设置 → 大肥鱼 → 会话压力（与“记忆”“会话与身份”同级）。页内仅三个子页签：当前、历史、指标。保持现有插件的视觉语言，不做独立 Dashboard。

| **页签** | **首屏内容**                                                                                     | **展开详情**                                                                             |
|----------|--------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------|
| 当前     | 当前累计综合分、当前轮/40、历史参考 100、Context/压缩余量、Session 实报总 Token、最近 5 轮增长。 | 按轮累计负担折线；高增长轮次榜；工具结果残留榜；点开轮次显示请求、工具、缓存与因子贡献。 |
| 历史     | Session 总数/已分析/归档数、有效样本量、不同轮数的典型与 P75 负担曲线、会话列表。                | 单 Session 峰值、结束分、实际压缩、模型路由、总 Token、数据可信度及参考阈值影响。        |
| 指标     | 七项独立开关、全部启用/恢复默认、自定义分与全指标分对照。                                        | 各项公式、原始量、历史基准、有效样本、当前贡献、关闭后分数变化与历史分布敏感度。         |

UI 文字使用中性表述：低于典型、接近典型、超过典型、明显超过典型。只有真实压缩余量不足时才显示独立警告。100 以上不是“系统异常”。

图表至少包括：（1）按轮累计分数曲线；（2）轮次/工具增长排行榜；（3）20/30/40 等不同轮数历史负担分布；（4）开关前后当前分与历史分布对照。图例必须分辨估算与实报，支持显示采样时间和数据覆盖。

# 十 数据完整度与可信度

| **状态** | **条件与 UI 文案**                                                         |
|----------|----------------------------------------------------------------------------|
| 完整     | 模型信息、有效窗口、关键请求 Usage、Surface 与工具历史均可重建，样本充足。 |
| 部分     | 缓存、早期 Usage 或一部分窗口数据不可得，仅计算可观测维度并注明覆盖率。    |
| 不足     | 历史样本或关键计量缺失严重；只展示原始统计，不伪造综合分。                 |

建议显示：有效历史 Session 数、可比较轮次数、总 Token 实报覆盖率、工具归因覆盖率、模型/策略分组以及最后一次更新的事件序号。建议阈值不足时只显示“样本不足”。

# 十一 本地计算和性能预算

- 零新增 LLM 请求、零外部查询；所有公式、统计和排名均由本地确定性代码计算。

- 事件驱动增量更新：新请求完成只更新相关计数；轮次结束保存快照；页面打开不全量扫描。

- 历史回填可暂停与继续，使用可取消的分批处理；不与前台聊天同步阻塞。

- 工具结果只保存大小、事件引用、可见次数和聚合数；不复制原文。

- 缓存带 eventSeq / logRevision、算法版本与配置版本，可恢复且可重算；禁止重复累加同一事件。

- 模型路由切换、压缩重写、Session Fork、恢复和事件不连续时，必须切分统计区间并保留来源标记。

# 十三 暂不实现及未来阶段

本阶段不做自动压力换房、压缩前拦截、自动修改轮次/阈值、人格恢复验证、长期记忆管理、模型价格换算或云端数据收集。

后续如考虑自动换房，仍沿用原有轮次条件（默认 40，可调）；任何压力触发必须由用户显式开启。那时应以压缩风险及实际收益为主，不能机械地将七维综合负担分用作“立即换房”命令。DSH pre-step 监听并不等于有可靠、可取消的压缩前钩子，需另行验证。

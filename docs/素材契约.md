# 素材契约（v1）

> 给写插件的第三方看的一页说明；也是我们自己接新来源时的唯一入口。
> 代码在 `lib/contract.js`（校验）与 `lib/sources.js`（来源登记）。

## 这是什么

一条「素材」= 她读到的一件事，带出处、带原话、带可不可核对。

契约不是要求所有工具都改。它是**认领制**：

- 一个工具照常返回一段文字 → 她照常当普通材料读，一切不变；
- 一个工具愿意按下面的形状返回 → 插件接住它，升级成素材：能引用原话、能进「同一件事」和「判断冲突」、能进体检里的八股统计。

不认领，就没有迁移成本；认领，才拿到分级与引用。

## 形状

工具的返回值可以是一段 JSON 字符串（推荐），也可以让调用方直接传对象。**整段必须是一个 JSON 对象**，不要在外面包「以下是结果：」这类话——认不出来就按普通文本处理。

```json
{
  "dshFishMaterial": 1,
  "source": "zhihu",
  "key": "https://www.zhihu.com/question/123/answer/456",
  "at": "2026-11-12",
  "title": "为什么大家都不愿意写注释",
  "kind": "opinion",
  "tags": ["编程", "习惯"],
  "facts": [{ "label": "回答数", "value": "42", "url": "https://…" }],
  "quotes": [
    { "text": "因为注释是写给未来的自己看的。", "kind": "answer", "by": "答主：某人" }
  ]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `source` | 是 | 来源名，1–40 字；要和设置里登记的来源一致 |
| `key` | 是 | 这一条的身份（URL / id / 编号），1–200 字；去重、回看都靠它 |
| `at` | 否 | 时间，能被 `new Date()` 读的字符串或毫秒数 |
| `title` | 否 | 标题，≤200 字 |
| `kind` | 否 | `fact` / `opinion` / `fiction`，**这是「它属于哪一类」，不是「它有多可信」** |
| `facts` | 否 | 可核对的事实项 `{ label, value, url? }`，最多 20 条 |
| `quotes` | 否 | 原话 `{ text, kind?, by?, like?, url? }`，最多 40 条、单句 ≤500 字 |
| `tags` | 否 | 最多 12 个短标签 |

`facts` 与 `quotes` 至少要有一个，否则算空素材，不收。

## 三条由插件说了算的规则

1. **级别不由来源自己定。**
   你只能声明 `kind`（这是事实 / 观点 / 虚构），最终能到几级由这张表决定：
   `fact → 1`、`opinion → 2`、`fiction → 3`。
   你在 `quotes[].grade` 里写一个更硬的数字也没用——只会被压回去，并记一笔 `grade-clamped`。

2. **声明「可核对」必须给锚。**
   1 级素材要么有 `facts`，要么这条原话带 `url`。都没有，就降成 2 级，记一笔 `fact-without-anchor`。
   我们宁可选一条能被点开的链接，也不选一句听起来很确定的话。

3. **原话一个字都不改。**
   内部空格、标点、引号全部保留，只裁首尾空白。不要替她总结、不要把口语改成书面语——
   能引用的东西才能被拿去核对。

## 不合规会怎样

不会报错，也不会让你整个工具失败：

- 缺 `source` / `key` → 整条不收（没有来路和身份，她引用时说不清是谁说的）；
- 空素材 / 超过长度上限 → 整条不收（`empty` / `too-long`）；
- 条数超了 → 截断并记一笔（`too-many-quotes` / `too-many-facts`）；
- 字符串不是 JSON → 按普通文本处理（`materialFromToolText` 返回 `null`）。

## 普通文本也能进来，但只能是观点

如果来源给的就是一段话（没有结构），可以用 `fromPlainText()` 包一下：
它保留全文、`canVerify` 为 `false`、所有引文都是 2 级。
这条路保证「进得了系统」，但进不了「可核对」。

## 现在接到哪了

- **B 站**：`lib/material.js` 的 `toMaterial()` 已经在走同一条 `coerceMaterial()`。它不是特例，
  校验器变严它也会跟着被拦——这是故意的，免得「自家的」和「外面的」两套标准。
- **第三方工具**：契约库与来源登记已就位（`lib/sources.js` 的 `sourceMaterial()`），
  但**还没有一个调用点**把第三方工具的结果送进来。原因是：要不要让第三方材料进系统，
  取决于设置里有没有登记这个来源、以及它走哪个工具——这一步是「新来源」的工作，
  不在本次契约里。在那之前，第三方材料仍按普通文本读。

接的时候只需要三行：拿到工具返回值 → `sourceMaterial(raw, { name, kind })` → 得到素材就
`renderMaterial()` 渲染、并记一条 `meta mat:<source>:<key>`（后者让回看和统计找得到它）。

## 设计边界

- 契约管**质量**，不管**频率**。它保证拿到的东西可核对，管不了她会不会去调这个工具。
- 等级**不进身份文档、不打分、不出现「几级」字样**。分级只用于渲染与后续判断。
- 不提供「可信度分数」。三个级别已经够用；再加数字就是把判断权交回给分数。

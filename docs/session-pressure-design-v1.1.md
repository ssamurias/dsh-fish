# DSH Session Pressure Analyzer
## 会话压力分析系统 · 完整技术设计文档

**文档版本：** 1.1
**整理日期：** 2026-11-16
**状态：** 源码核对后更新
**适用项目：** dsh-fish 会话压力分析插件

---

# 1. 项目概述

## 1.1 项目目标

本系统旨在通过完全本地化的统计和计算，对 DeepSeek Harness（DSH）中的 Session 运行状态进行诊断、评分、历史比较和趋势预测。

核心目标是回答：

1. 当前 Session 的上下文及请求负担有多大？
2. 压力主要来自哪些因素？
3. 当前状态与用户历史 Session 相比处于什么位置？
4. 最近压力如何变化？
5. 如果继续对话，未来压力可能如何发展？
6. 当前是否有明显的容量风险，是否值得考虑新建 Session？

系统并不试图直接衡量模型的智力、实际回答质量或用户满意度。

## 1.2 设计原则

### 原始数据与评分分离

所有诊断数据必须保留其原始读数、单位、来源、统计范围及计算口径。

修改评分公式不得影响原始诊断数据。

### 多视角而非单一评分

系统保留三种独立综合压力：

- A · 分层加权
- B · 非线性合成
- C · 容量主导修正

不得再次合成为第四个最终分数。

### 尽量避免重复惩罚

同一 Token 可以同时影响多个诊断维度，但在综合评分时应明确各维度职责，避免无意义地重复累加。

### 数据缺失不等于零

所有缺失数据应明确标记。

只有具备证据的真实零值才能参与正常计算。

### 历史分析可复现

历史 Session 的第 N 轮必须使用截至第 N 轮能够获取的数据计算。

不得使用未来状态回填过去。

### 本地计算

所有诊断、评分、历史比较、预测和归因均应在本地完成。

不需要额外 AI 模型调用。

# 2. 系统整体架构

系统由六个逻辑层组成：

1. 原始数据采集
2. 七项诊断指标
3. 三个子压力
4. 三种综合压力
5. 历史分析与预测
6. 首页用户解释与建议

数据流：

```text
DSH Session 原始记录
          │
          ▼
七项诊断数据
C / G / U / A / T / K / E
          │
          ▼
三个子压力
C+G / U+A+K / T+E
          │
          ▼
三种综合压力
A / B / C
          │
          ├── 当前状态
          ├── 历史同轮比较
          ├── 多 Session 趋势
          ├── 预测回测
          └── 变化归因

C 实际占用 + G 实时增长 → 首页实验建议
```

# 3. 七项诊断指标

## 3.1 C · 上下文容量

目标：衡量当前上下文占用了多少有效窗口空间。

核心数据：

- 最新有用量请求的输入 Token
- 同一次请求的有效上下文窗口
- 当前窗口占用率
- 剩余 Token
- 系统消息独立字段占用
- 工具定义占用
- 压缩前后配对读数

基础公式：

\[
c=\frac{I_{\text{latest}}}{W}
\]

其中：

- \(I_{\text{latest}}\)：最新有用量请求的输入 Token
- \(W\)：该请求对应的有效上下文窗口

原始占用率允许超过 100%，但用于评分的输入限制在 0–1。

如果独立 `system` 字段为空或缺省，可显示 0 Token。

这不代表系统指令不存在于请求其他部分。

整条请求头缺失时，应显示未知。

## 3.2 G · 增长负担

目标：衡量上下文消耗速度及近期变化趋势。

记录：

- 逐轮净变化
- 最近 5 轮平均净增长
- 最近 10 轮平均净增长
- 最近 20 轮平均净增长
- 正向增长量
- 短期与中期增长差
- 压缩及裁剪事件
- 可比较轮次差值数量

基础计算：

\[
g_i=c_i-c_{i-1}
\]

默认趋势估计：

\[
g=0.5g_5+0.3g_{10}+0.2g_{20}
\]

其中 \(g\) 使用百分点/轮。

历史窗口缺失时，对可用窗口的权重重新归一化。

不得将缺失窗口视为零增长。

压缩或上下文窗口变化可能导致增长率出现结构性变化，需要保留事件标记。

## 3.3 U · Token 用量

目标：记录 Session 累计模型处理量。

区分：

- 累计请求输入（包含缓存）
- 累计输出
- 成功请求总用量
- 常规模型请求总用量（包含失败尝试）
- 独立压缩调用用量
- 每轮平均 Token
- 请求次数

基本公式：

\[
U_{\text{success}}=\sum(I_j+O_j)
\]

累计 Token 不直接等于 API 成本。

不同输入、缓存输入、输出及模型可能具有不同成本。

## 3.4 A · 请求放大

目标：衡量同一用户轮内，首次请求之后追加了多少模型输入。

每轮记录：

- 成功请求数
- 失败尝试数
- 首次成功请求输入
- 后续成功请求输入
- 输入放大率
- 工具调用后继续推理次数（能够可靠识别时）

公式：

\[
A_i=\frac{\sum_{j=2}^{m}I_j}{I_1}
\]

当首请求输入为零或缺失时，应明确处理不可计算情况。

A 的追加输入已经包含于 U，不应在请求负担中重复按原始 Token 加权。现行 `load.A` 在存在失败尝试，或后续请求用量不完整时可能缺失，指标页据此显示。

## 3.5 T · 工具结果残留

目标：衡量当前上下文中的工具结果占用，以及历史上的跨轮重复携带。

核心数据：

- 当前可见工具结果 Token
- 当前工具残留占比
- 历史累计工具结果携带
- 跨轮重复携带
- 工具结果产生轮次
- 后续携带次数
- Token 加权残留年龄
- 工具结果裁剪和压缩状态

当前残留比例：

\[
t_c=\frac{T_{\text{current, est}}}{I_{\text{host, est}}}
\]

历史重复携带比例：

\[
t_r=\frac{T_{\text{cross-round}}}{I_{\text{matched}}}
\]

当前比例的分子、分母来自同一宿主请求可见上下文，使用同一 DSH 消息与内容块估算口径。分母包含可重建的请求输入和已记录的封装。模型提供商实报输入单独展示；提供商最终接收内容的工具分项不可直接验证。历史重复携带同样逐请求配对，再对匹配估算量求和。

历史重复携带是累计工具携带的一部分，不应与累计携带量直接相加。

已知曾出现残留比例超过 100% 的问题。

代码按请求边界重建，处理替换、压缩、裁剪和同调用重复结果。没有可见消息时，即使有实报用量或请求头，当前残留依然未知。已标记入面消息缺字段、无法还原替换范围等情况同样不可计算。保留实报用量和缺失原因，历史比例仅使用匹配请求。可重建的有效请求明确无工具时可以显示零。评分遵循以下不变量：

- 相同请求快照
- 相同 Token 计量口径
- 压缩和裁剪正确识别
- 不重复计数
- 异常值不能静默封顶后进入评分

工具结果大小可能存在估算误差，必须保留来源及估算标记。

## 3.6 K · 缓存复用

目标：衡量模型输入中的缓存复用情况。

记录：

- 有缓存报告的输入
- 缓存命中输入
- 未缓存输入
- 缓存未命中率
- 缓存报告覆盖率
- 最近 5、10 轮缓存表现

公式：

\[
K_{\text{miss}}=
1-\frac{I_{\text{cached}}}{I_{\text{reported}}}
\]

只使用具有有效缓存报告的请求。

没有缓存报告时不得假定全部未命中或全部命中。

覆盖率为零时，未命中率显示未知。

## 3.7 E · 失败与恢复

目标：衡量明确失败与恢复产生的额外负担。

记录：

- 模型失败尝试
- 模型失败率
- 工具失败
- 工具失败率
- 同轮、同步骤已匹配的重试
- 已归因失败尝试 Token
- 已知限制：独立恢复调用、统一错误分类和语义失败统计尚未完整实现

优先使用能够明确归因的 Token 消耗。

不能仅因为发生工具失败，就假设产生了某个固定 Token 成本。

无法确认的语义失败不得猜测。

# 4. 三个子压力模块

所有子压力最终映射至 0–100 分。

以下参数均为实验默认值，尚未经充分历史数据校准。

## 4.1 C+G · 容量压力

纯容量压力：

\[
S_C=100c^\gamma
\]

默认：

\[
\gamma=2
\]

增长趋势：

\[
g=0.5g_5+0.3g_{10}+0.2g_{20}
\]

未来 H 轮预计消耗的剩余空间比例：

\[
G_H=
\operatorname{clamp}
\left(
\frac{H\max(g,0)}{100(1-c)},0,1
\right)
\]

其中 g 的单位为百分点/轮。

复合容量压力：

\[
P_C=
100[1-(1-c^\gamma)(1-\lambda G_H)]
\]

默认：

- γ = 2
- H = 10 轮
- λ = 0.35

当 c=1 时，容量压力定义为 100。

未来占用情景：

\[
\hat c_{n+H}=
\operatorname{clamp}(c_n+Hg/100,0,1)
\]

这是固定增长趋势下的情景推演，不是保证实际发生的结果。

## 4.2 U+A+K · 请求负担

每轮有效处理量：

\[
L_i=I_{u,i}+\rho I_{c,i}+\beta O_i
\]

参数：

- ρ：缓存命中输入折算系数
- β：输出 Token 折算系数

默认：

- ρ = 1
- β = 1

缓存报告缺失时保留不确定性上下界。

默认保守上界将未知缓存输入按全额折算。

长期与近期联合：

\[
R=
\frac{0.4\overline L_{\text{all}}+
0.6\overline L_{10}}{W}
\]

请求压力：

\[
P_R=100(1-e^{-R/\tau})
\]

默认：

\[
\tau=1
\]

A 产生的追加请求输入已经包含于有效处理量。

不额外增加独立 A 惩罚。

ρ=1 时缓存命中不会改变得分，应在 UI 中说明缓存修正未实际生效。

## 4.3 T+E · 结构与稳定性

结构负担：

\[
T_s=w_t t_c+(1-w_t)t_r
\]

默认：

\[
w_t=0.7
\]

失败负担：

\[
E_s=1-e^{-e_r/\epsilon}
\]

默认：

\[
\epsilon=0.05
\]

其中 \(e_r\) 为已归因重试 Token 占对应总用量的比例。

复合结构压力：

\[
P_Q=100[1-(1-T_s)(1-\eta E_s)]
\]

默认：

\[
\eta=0.3
\]

工具残留年龄保留为诊断指标，目前不直接进入评分。

工具结果占比高不代表内容无用，也不直接意味着需要切换 Session。

# 5. 三种综合压力

首先将三个子压力转换到 0–1：

\[
c=P_C/100,\quad r=P_R/100,\quad q=P_Q/100
\]

## 5.1 A · 分层加权

\[
P_A=
100\frac{w_cc+w_rr+w_qq}{w_c+w_r+w_q}
\]

默认：

- 容量权重 0.50
- 请求权重 0.30
- 结构权重 0.20

权重总和为零时显示不可计算。

## 5.2 B · 非线性合成

\[
P_B=
100[1-(1-c)^{w_c}(1-r)^{w_r}(1-q)^{w_q}]
\]

默认风险强度：

- 容量 0.50
- 请求 0.30
- 结构 0.20

风险强度不强制归一化。

某个强度为零时对应维度不参与。

全部强度为零时，按当前实验定义返回零分，并标明贡献关闭。

## 5.3 C · 容量主导修正

\[
M=\frac{w_rr+w_qq}{w_r+w_q}
\]

\[
P_C^*=100[c+\mu(1-c)M]
\]

默认：

- 请求权重 0.60
- 结构权重 0.40
- μ = 0.35

当请求和结构权重之和为零时，M=0。

容量为 100 分、其余子压力缺失且使用默认参数时，A 无法计算。B 的容量剩余因子为零，C 无剩余容量可修正，所以 B/C 仍确定为 100。显式 T 异常优先作废依赖的 A/B/C。

## 5.4 不进行二次合成

A/B/C 始终独立展示。

不得再做一次加权平均形成第四个压力分。

历史比较、趋势预测和归因分析均可对三个方案分别执行。

# 6. 页面架构

插件采用四个一级页面：

- 当前
- 历史
- 指标
- 计算

## 6.1 当前页

这是默认首页，目标是快速说明当前 Session 状态。

页面结构：

### 会话信息

显示：

- Session 名称
- 模型
- 已完成轮次
- 最后数据更新时间
- 数据完整性

有效窗口可在首页建议依据和指标页查看。

### 状态与建议

使用自然语言给出当前建议。

候选状态：

1. 继续使用
2. 继续使用，留意变化
3. 建议准备新会话
4. 强烈建议切换
5. 数据不足，暂不能判断

建议由本地确定性规则生成。

现行实现按 C 实际窗口占用与 G 实时增长判定，缺少占用时显示数据不足。

### A/B/C 三张综合评分卡

每张显示：

- 当前实时压力
- 最近完成轮变化（5 轮）
- 轮末历史同轮次百分位及中位数差值

实时 G 只用同配置的可比轮末采样。历史 G 可回退到相邻轮请求实报占用率。实时分缺失时，轮末分或历史百分位仍可能可用。

没有历史样本时显示未知和样本数量。

### 压力走势

默认显示最近 20 轮的 A/B/C 曲线。

支持 10、20、50、全部轮次切换。

### 三个子压力

显示容量、请求、结构压力及近期变化。

### 关键诊断摘要

突出：

- 上下文占用
- 剩余窗口
- 增长趋势
- 请求负担
- 工具残留
- 缓存覆盖情况

### 近期事件

折叠展示真实模型切换、压缩、裁剪和失败记录。

## 6.2 历史页

包含四个二级视图。

### Session 对比

支持最多五个 Session 同时绘制。

各自显示真实存在的轮次。

缺失轮次不补零、不延长、不插值。

多 Session 模式默认比较一种综合公式。

### 同轮次比较

选择第 N 轮，使用历史各 Session 的第 N 轮数据。

提供：

- 当前分数
- 历史中位数
- 百分位
- 差值
- 样本数

默认允许跨模型、跨窗口比较，但必须提示归一化不等于完全可比。

### 预测回测

包含：

- MAE 比较
- 偏差比较
- 共同样本筛选
- 真实值与预测值曲线
- 逐次预测详情

### 变化归因

支持选择任意两个有效轮次，分析子压力变化、数学贡献及对应事件。

## 6.3 指标页

保留七项诊断的原始数据与完整口径。

使用七张概览卡及独立折叠明细。

还应提供：

- 上下文组成
- Token 用量
- 缓存报告覆盖
- 工具结果当前残留
- 历史累计工具携带
- 逐轮记录
- 压缩与裁剪事件

所有显示必须标明单位、来源、统计范围和数据状态。

## 6.4 计算页

保留三个子压力计算卡：

- C+G
- U+A+K
- T+E

及三个综合公式卡：

- A
- B
- C

每个卡片支持：

- 参数调整
- 默认值重置
- 中间结果
- 公式展开
- 当前数据来源

修改参数后重新计算所有受影响的历史结果。

# 7. 历史同轮次比较

## 7.1 核心规则

当前查看第 N 轮时，只使用历史 Session 第 N 轮的数据。

历史 Session 不必达到当前 Session 的最新轮数，才能展示其已有历史曲线。

例如：

- 当前 Session：65 轮
- 历史 A：107 轮
- 历史 B：50 轮

查看第 40 轮时，三个 Session 均可候选参与。

查看第 65 轮时，历史 B 不参与统计，但其 1–50 轮曲线仍保留。

## 7.2 百分位

采用中秩百分位：

\[
p=100\frac{N_<+0.5N_=}{N}
\]

当前 Session 不纳入自己的历史样本。

百分位代表相对历史位置，不代表失败概率或换房收益。

## 7.3 模型与窗口

允许混用模型或上下文窗口的 Session。

每一轮使用其真实模型和有效窗口进行归一化。

模型或窗口切换要标记。

跨模型比较具有局限性，不得宣称所有压力分天然具有完全一致的真实运行含义。

# 8. 压力预测与回测

## 8.1 现有方法

候选预测方法：

1. 最近 5 轮线性
2. 最近 10 轮线性
3. 最近 5/10/20 轮加权

从第 20 轮开始，每隔 5 轮生成一次预测。

预测提前量：

- 5 轮
- 10 轮
- 20 轮

每次预测只能使用预测起点及以前的数据。

## 8.2 评估指标

平均绝对误差：

\[
MAE=\frac1N\sum_i|\hat P_i-P_i|
\]

平均偏差：

\[
Bias=\frac1N\sum_i(\hat P_i-P_i)
\]

正偏差代表高估。

负偏差代表低估。

比较不同预测方法时，应提供共同样本模式。

因为预测有效次数不同，直接比较全部样本 MAE 可能产生偏差。

## 8.3 图表

应包括：

- MAE 分组柱状图
- 正负预测偏差柱状图
- 真实压力与预测压力对比折线图

图表支持 A/B/C 切换。

真实值使用实线，预测值使用虚线。

预测起点和目标轮次必须明确。

## 8.4 当前研究结论

根据此前提供的历史样本：

- 短期 5 轮预测通常比 10–20 轮更稳定。
- 线性趋势可能出现长期高估。
- 历史压力突变也可能导致严重低估。
- 结构性事件会影响预测可靠性。
- 历史 Session 数量有限，尚不足以可靠选择唯一预测算法。

在 T 修复后的一次同样本回测报告中：

| 提前轮数 | 修复前 MAE | 修复后 MAE | 预测次数 |
|---|---:|---:|---:|
| 5 | 4.79 | 4.71 | 51 |
| 10 | 11.57 | 11.12 | 42 |
| 20 | 12.45 | 10.15 | 24 |

这组数据来自此前特定回放批次，涵盖 5 个 Session、223 个完成轮和当时的 63 项针对性测试。表中数据为当批已选历史共同样本的结果。

# 9. 压力变化归因

## 9.1 基本功能

用户选择：

- Session
- 起始轮次
- 结束轮次
- 综合公式 A/B/C

系统显示：

- 三个子压力在起止轮次的变化
- 三种综合压力的变化
- 七项诊断变化
- 区间内已记录的结构性事件

## 9.2 A 的贡献计算

线性权重不变时：

\[
D_i=\frac{w_i}{\sum w}\Delta P_i
\]

三项贡献之和等于综合压力变化。

## 9.3 B/C 的贡献计算

使用三个子压力的 Shapley 分解。

枚举三个变量的六种替换顺序，平均计算各变量边际贡献。

满足：

\[
D_c+D_r+D_q=P_{\text{end}}-P_{\text{start}}
\]

允许负贡献。

贡献表示公式内部的数学影响，不证明现实因果关系。

## 9.4 结构事件

关联：

- 模型切换
- 有效窗口变化
- 压缩
- 工具结果裁剪
- 显式失败
- 已匹配重试

事件必须来自真实记录。

不得根据压力突变虚构事件。

## 9.5 预测误差归因

从回测详情跳转至对应预测区间。

显示：

- 起点
- 目标轮
- 预测值
- 实际值
- 误差
- 子压力预测与实际差异
- 可用的 Shapley 误差贡献

预测值重算时禁止使用起点之后的数据。

# 10. 首页建议逻辑

## 10.1 核心原则

首页建议与 A/B/C 压力评分是两个相关但不同的系统。

A/B/C 用于综合观察。

建议主要依据：

- 当前实际窗口占用
- 剩余容量
- 近期增长
- 短期容量情景预测
- 数据完整性

T 高不直接意味着必须换房。

累计 Token 高也不直接意味着必须换房。

## 10.2 实验状态

建议状态：

- 继续使用
- 继续使用，留意变化
- 建议准备新会话
- 强烈建议切换
- 数据不足

最初讨论的实验阈值：

- 当前占用低于 70%，预计十轮后未达到 85%：继续使用
- 当前占用达到 70%，或十轮后预计达到 85%：留意变化
- 当前占用达到 85%，或五轮后预计达到 95%：准备新会话
- 当前占用达到 95%：强烈建议切换

应按照风险从高到低应用规则。

这些是设计候选值，不能宣称已经经过历史实证校准。

现有代码采用这些优先级和阈值。最高等级只由实测占用达到 95% 触发。缺少可比走势时仍可依据实际占用判定，预测为空。A/B/C、累计 Token 和工具残留用于分析。宿主的 `chat.rotateAfter` 是独立的按轮轮换功能。

## 10.3 用户文案

推荐使用简单自然语言：

「当前仍有较多上下文空间，可以继续使用。」

「最近几轮增长较快，建议关注后续变化。」

「当前上下文已经接近有效窗口上限，可以考虑在下一段任务前切换会话。」

「工具结果残留占比较高，但目前没有证据表明必须立即切换。」

必须给出真实的主要依据。

不得声称换房一定节约成本或改善回答质量。

# 11. 数据缓存与存储

## 11.1 原始数据

Session 原始记录是重建历史分析的基础。

本插件不应修改原始 Session 内容。

## 11.2 可重建派生数据

完整 Session 日志及留存的原始观测可用于重建请求诊断、子压力、A/B/C、历史趋势和回测。回测和趋势按需计算。源码中的评分公式版本保持原值，配置可变后重新计算。

## 11.3 分析检查点与快照

- `session-pressure-cache/<Session ID>.json` 保存分析检查点、日志游标、长度和末条事件摘要。v1.0 的旧检查点为 v9。修复 T 缺失判定后使用 v10，读取时拒绝旧版并按日志重建。
- `session-pressure-cache/pressure-v0.2/` 保留此前的 `diagnostics-v2` 轮末快照。新版快照另写入 `session-pressure-cache/pressure-v0.3/`，标识 `diagnostics-v3`。快照记录公式版本、参数与来源指纹。历史比较实行同诊断版本与同轮次约束。
- 原始 Session 文件和采样仍保留。原始日志丢失或覆盖不完整时，无法保证全部诊断可恢复。

## 11.4 原始观测与备份

`logs/session-pressure/samples.json` 中的 `records` 是轮末 meter 采样，`compactions` 是最近成功配对，`compactionPairs` 按事件序号保存压缩前后读数。事件日志可重建部分请求占用和事件，但不能保证重现这些原始观测。

原文件仍使用同一路径，升级无需迁移。手动及自动备份（包括核心模式）将该文件作为普通日志排除规则的单文件例外，其余日志继续排除。备份仍遵循既有容量上限和跳过回执。旧包恢复时保留本机采样；新包恢复与本机采样按 Session 和事件序号合并，共用键保留恢复前本机记录。原文件仍可在恢复隔离目录查询。

## 11.5 写入队列

根据最近一次开发检查报告：

- `mutateJson` 负责同路径的进程内排队。
- `writeAtomic` 负责实际文件写入。
- 两者不是重复写入。
- 回调中的 `writeAtomic` 不能直接移除。
- 同进程、同队列写入受到顺序保护。
- 跨进程或绕过队列的写入不受该队列保护。

相关报告称 23 项测试通过。

另有独立发现：`talkmem.js` 中 `amendLastExchange` 可能绕过另一写入队列。

该问题不属于本次压力分析核心功能，尚未在本项目中处理，应记录为外部/相邻模块的潜在并发风险，不可声称已经修复。

# 12. 数据质量与缺失处理

## 12.1 基本规则

必须区分：

- 精确统计
- 可重建统计
- 估算
- 缺失
- 异常

不得使用假零填补缺失。

## 12.2 已知数据限制

根据已有报告：

- 部分历史轮次缺少 E 数据。
- 某些轮次无法构建完整的 G 配对采样。
- 工具结果 Token 曾存在估算口径不一致问题。
- 部分历史 Session 混用模型和上下文窗口。
- 历史样本数量较少。
- 压缩与裁剪可能导致趋势发生结构性变化。

实时评分可能因缺少可比 G 采样、T 请求上下文不完整、E 无法归因等原因显示不可用。

这些限制不代表所有轮次都不可用。

## 12.3 数据异常时的行为

不能因异常值超过范围就静默封顶后显示正常评分。

应当：

1. 保留异常原始读数。
2. 标记原因。
3. 排除无法可靠计算的评分。
4. 显示缺失的具体字段。
5. 不污染历史百分位和回测。

# 16. 最终产品定位

DSH Session Pressure Analyzer 不是一个简单的 Token 计数器，也不是自动换房工具。

它是一个本地化的 Session 运行诊断与研究系统：

- 通过七项指标观察真实负担。
- 使用三组子压力组织复杂数据。
- 通过 A/B/C 三种算法提供不同视角。
- 利用历史同轮次比较理解当前相对位置。
- 利用回测衡量趋势预测的可信程度。
- 利用数学归因解释压力变化。
- 在首页将复杂结果翻译成简单、透明、可核查的建议。

最终目标不是制造一个看起来精确的单一数字，而是帮助用户真正理解 Session 的运行状态，并逐渐建立有数据依据的使用习惯。
